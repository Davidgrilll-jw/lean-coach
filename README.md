# Lean Coach

เว็บแอปส่วนตัวสำหรับติดตามการลดไขมันและรักษากล้ามเนื้อ: อาหาร น้ำหนัก รอบเอว เวท กิจกรรม รายงานรายสัปดาห์ และ Plateau Detector
ใช้งานได้บนมือถือ (iPhone/Android) และ Desktop ติดตั้งเป็น PWA ได้ ภาษาไทยเป็นหลัก

## เริ่มใช้งาน

ต้องมี Python 3.9 ขึ้นไป (ไม่ต้องติดตั้งแพ็กเกจเพิ่ม ไม่ต้อง build)

```bash
cd lean-coach
python server.py
```

แล้วเปิด <http://localhost:5173>

- เปลี่ยนพอร์ต: `python server.py --port 8080`
- เปิดจากมือถือในวง Wi-Fi เดียวกัน: `python server.py --host 0.0.0.0` แล้วเข้า `http://<IP เครื่องคอม>:5173`
  (ใช้งานและบันทึกข้อมูลได้ แต่การติดตั้งเป็นแอป/ออฟไลน์ต้องเป็น HTTPS — ดูหัวข้อ Deploy)

แอปเป็นไฟล์ static ล้วน จะใช้เซิร์ฟเวอร์ static ตัวอื่นแทนก็ได้ `server.py` มีไว้เพื่อ (1) ส่ง MIME type ของไฟล์ `.js` ให้ถูกบน Windows และ (2) ให้บริการ AI Coach ซึ่งเป็นทางเลือก

## ทดสอบ

ชุดทดสอบครอบคลุมสูตร BMR/TDEE การรวมสารอาหาร ค่าเฉลี่ย 7 วัน อัตราการลด Plateau Detector การแนะนำเพิ่มน้ำหนักเวท รายงานรายสัปดาห์ การตรวจสอบข้อมูล และชั้นจัดเก็บข้อมูล (43 รายการ)

- ในเบราว์เซอร์: รัน `python server.py` แล้วเปิด <http://localhost:5173/tests/index.html>
- ด้วย Node 18+ (ถ้ามี): `node tests/run-node.mjs`

## Tech stack และเหตุผล

| ส่วน | ที่ใช้ | เหตุผล |
|---|---|---|
| Frontend | HTML + CSS + JavaScript (ES Modules) ไม่มี framework ไม่มีขั้นตอน build | เครื่องที่พัฒนาไม่มี Node.js จึงเลือกแบบที่รันและทดสอบได้จริงทันที และ deploy เป็นไฟล์ static ได้ทุกที่ |
| กราฟ | SVG เขียนเอง (`js/ui/charts.js`) | ไม่ต้องพึ่ง library ภายนอก ใช้งานออฟไลน์ได้ |
| จัดเก็บข้อมูล | IndexedDB ในเบราว์เซอร์ | ใช้คนเดียว ใช้ได้ทันที เก็บรูปได้ ไม่ต้องมีบัญชี |
| Backend (ทางเลือก) | `server.py` (Python standard library) + `anthropic` SDK | เก็บ API key ฝั่งเซิร์ฟเวอร์สำหรับ AI Coach |
| PWA | `manifest.webmanifest` + `sw.js` | ติดตั้งบนหน้าจอมือถือและเปิดออฟไลน์ได้ |

## ข้อมูลและความเป็นส่วนตัว

- ข้อมูลทั้งหมด (รวมภาพรูปร่าง) เก็บใน IndexedDB ของเบราว์เซอร์บนอุปกรณ์นั้น **ไม่ถูกส่งขึ้นเซิร์ฟเวอร์**
- ข้อมูล**จะหาย**เมื่อล้างข้อมูลเว็บไซต์/เบราว์เซอร์ ถอนการติดตั้งแอป หรือเปลี่ยนอุปกรณ์ และ**ไม่ซิงก์ข้ามอุปกรณ์**
  → ใช้ ตั้งค่า › สำรองข้อมูล เป็นระยะ และ ตั้งค่า › กู้คืนจากไฟล์ บนอุปกรณ์ใหม่
- iPhone: Safari อาจลบข้อมูลของเว็บที่ไม่ได้เปิดนานราว 7 วัน การ "เพิ่มไปยังหน้าจอโฮม" ช่วยให้ข้อมูลอยู่ถาวรกว่า และควรสำรองไฟล์ไว้เสมอ
- ไฟล์สำรองเป็น JSON ไม่เข้ารหัส แบบ "รวมภาพ" จะมีภาพรูปร่างอยู่ด้วย
- ค่าโภชนาการในฐานข้อมูลอาหารเริ่มต้นเป็น**ค่าประมาณ**จากตารางคุณค่าอาหารทั่วไป แก้ไขได้ทุกรายการในเมนู อาหาร › ฐานข้อมูลอาหาร

### ย้ายไปฐานข้อมูลบนเซิร์ฟเวอร์ในอนาคต

UI เรียกเฉพาะ `js/store/repo.js` ซึ่งคุยกับ adapter ที่มี 4 เมธอด (`getAll`, `put`, `remove`, `clear`)
เขียน adapter ใหม่ที่เรียก REST API แล้วส่งให้ `repo.init(adapter)` ได้โดยไม่ต้องแก้หน้าจอ
`docs/schema.sql` มีตารางครบ 15 ตารางตามที่ออกแบบ (Users … UserGoals) พร้อม `user_id` ทุกตารางสำหรับแยกข้อมูลรายผู้ใช้
ทุก record ในแอปมี `userId` อยู่แล้ว (ตอนนี้เป็น `local`)

## เป้าหมายโภชนาการเริ่มต้นคำนวณอย่างไร

เปิดแอปครั้งแรกจะเป็นค่าตัวอย่าง ให้กรอกโปรไฟล์ของตัวเองที่ ตั้งค่า › โปรไฟล์ แล้วกดบันทึก ระบบจะตั้งเป้าหมายเริ่มต้นให้ตามนี้

| ค่า | วิธีคิด |
|---|---|
| BMR | สูตร Mifflin–St Jeor จากเพศ อายุ ส่วนสูง และน้ำหนัก (ใช้ค่าเฉลี่ยน้ำหนักที่ชั่งจริงเมื่อมีข้อมูล) |
| TDEE | BMR × ตัวคูณระดับกิจกรรม (1.2–1.9) ตัวคูณรวมการออกกำลังกายไว้แล้ว จึง**ไม่บวก**แคลอรีจากการออกกำลังกายซ้ำ |
| แคลอรีเป้าหมาย | ต่ำกว่า TDEE ราว 18% ปัดเป็นหลัก 50 และไม่ต่ำกว่า BMR |
| โปรตีน | 2.0 ก./กก. — เหมาะกับการรักษากล้ามเนื้อช่วงขาดดุลพลังงาน |
| ไขมัน | 0.75 ก./กก. |
| คาร์โบไฮเดรต | พลังงานส่วนที่เหลือ (โปรตีนและคาร์บ 4 kcal/ก. ไขมัน 9 kcal/ก.) |
| ก้าว | เริ่มที่ 6,000 แล้วเพิ่มเป็น 7,000–8,000 เมื่อทำได้สม่ำเสมอ 2 สัปดาห์ |

ทั้งหมดเป็นค่าประมาณเริ่มต้น แก้ได้ที่หน้าตั้งค่า เมื่อบันทึกอาหารครบ ≥14 วันและชั่งน้ำหนัก ≥10 วันใน 3 สัปดาห์ แอปจะแสดง **TDEE จากข้อมูลจริง** ให้เทียบ

หมายเหตุเรื่องโปรตีน: แอปไม่เคยถือว่าน้ำหนักเนื้อสัตว์เท่ากับโปรตีน เช่น อกไก่สุก 150 ก. = โปรตีน ~46.5 ก.
ให้บันทึกอาหารจริง 3–7 วันเพื่อดูว่าได้โปรตีนถึงเป้าหมายหรือไม่

## กติกาของ Plateau Detector

- ใช้ค่าเฉลี่ย 7 วันและแนวโน้ม 21 วัน ไม่ตัดสินจากน้ำหนักวันเดียว
- ต้องมีการชั่ง ≥4 วันในแต่ละสัปดาห์ของ 2 สัปดาห์ล่าสุด, ≥10 วันใน 21 วัน และครอบคลุม ≥14 วัน ไม่เช่นนั้นจะแจ้งว่า "ข้อมูลยังไม่พอ"
- น้ำหนักนิ่ง = แนวโน้มเปลี่ยนน้อยกว่า 0.15 กก./สัปดาห์ · ช่วงที่เหมาะสม = ลด 0.25–0.75% ของน้ำหนักตัว/สัปดาห์
- ดูรอบเอว (2 ครั้งห่างกัน ≥10 วัน) ความครบถ้วนของการบันทึกอาหาร (≥10 จาก 14 วัน) ก้าวเดิน และจำนวนครั้งเวทประกอบ
- เสนอปรับครั้งละน้อย (−100 kcal หรือ +1,000 ก้าว) **ต้องกดยืนยันเองทุกครั้ง** ไม่ลดจนต่ำกว่า BMR × 1.05 และหลังปรับแล้วจะไม่เสนอปรับซ้ำภายใน 14 วัน

## AI Coach (ทางเลือก)

รายงานรายสัปดาห์ทำงานได้ครบด้วยกฎคำนวณโดยไม่ต้องมี AI หากต้องการคำอธิบายเพิ่มจาก Claude:

```bash
pip install -r requirements.txt
copy .env.example .env        # macOS/Linux: cp .env.example .env
# แก้ .env ใส่ ANTHROPIC_API_KEY
python server.py
```

- API key อยู่ใน `.env` ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่ถูกส่งไปเบราว์เซอร์ และ `server.py` ไม่เสิร์ฟไฟล์ `.env`
- ส่งเฉพาะตัวเลขสรุปของสัปดาห์ ไม่ส่งรูปหรือรายการอาหารรายชิ้น
- ถ้า API ใช้ไม่ได้ หน้ารายงานจะแจ้งและยังแสดงรายงานตามกฎตามปกติ
- **ยังไม่ได้ทดสอบกับ API จริง** เพราะเครื่องที่พัฒนาไม่มี API key และไม่ได้ติดตั้ง SDK — ทดสอบแล้วเฉพาะเส้นทางสำรอง (ไม่มี key → `/api/health` ตอบ `ai: false`, `/api/coach` ตอบ 503)

## Deploy

**ยังไม่ได้ deploy ขึ้นอินเทอร์เน็ต** — ทดสอบแล้วบน `localhost` เท่านั้น ขั้นตอนเมื่อพร้อม:

**แบบ static (แนะนำ, ฟรี, ได้ HTTPS → ติดตั้งเป็นแอปบนมือถือได้)**
อัปโหลดทั้งโฟลเดอร์ `lean-coach/` ไปที่ GitHub Pages, Netlify, Cloudflare Pages หรือ Vercel ไม่ต้องตั้งค่า build
(ไม่จำเป็นต้องอัปโหลด `server.py`, `tests/`, `tools/`, `docs/`, `.env*`) ฟีเจอร์ทั้งหมดใช้ได้ยกเว้น AI Coach

**แบบมี AI Coach**
รัน `server.py` บนบริการที่รัน Python ได้ (Render, Fly.io, Railway, VPS) ตั้ง `ANTHROPIC_API_KEY` เป็น environment variable ของบริการ
และวางหลัง HTTPS เนื่องจากเซิร์ฟเวอร์นี้ไม่มีระบบล็อกอิน ควรจำกัดการเข้าถึง (เช่น Cloudflare Access หรือ basic auth ที่ reverse proxy) เพื่อไม่ให้คนอื่นใช้โควตา API

เมื่อแก้ไฟล์แล้ว deploy ใหม่ ให้เปลี่ยนค่า `CACHE` ใน `sw.js` (เช่น `lean-coach-v2`) เพื่อให้เครื่องผู้ใช้ทิ้งไฟล์เก่า

## สิ่งที่ยังไม่ได้ทำ

- เชื่อมต่อ Apple Health / Google Fit — เว็บแอปเข้าถึงข้อมูลเหล่านี้โดยตรงไม่ได้ ต้องมีแอป native หรือบริการตัวกลาง ตอนนี้กรอกก้าวเอง
- บัญชีผู้ใช้และ Cloud Sync — โครงสร้างรองรับแล้ว (adapter + `docs/schema.sql`) แต่ยังไม่มี backend
- การแจ้งเตือน (push notification)

## ข้อจำกัดความรับผิดชอบ
